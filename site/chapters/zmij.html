Żmij: candidate selection is only half the pipeline

Żmij inherits Schubfach-family interval geometry, schedules the final digit from one farther-scaled product, and treats conversion of the selected integer into character bytes as first-class work.

Z.1 · What is and is not new

The parsing interval comes from Schubfach

Żmij does not require a new definition of the shortest recovering decimal. Its distinctive object is an implementation pipeline in which selection and byte production are scheduled together.

The regular binary64 path estimates the decimal exponent, loads a cached 128-bit power, and retains the upper 128 bits of a conceptual 192-bit product. The pinned source describes one cached-power multiplication rather than the three-coordinate formulation of straightforward Schubfach. An irregular power-of-two path remains separate because its two margins differ.

Z.2 · Executable semantic x-ray

Follow the dependency edges, then follow the digits into bytes

The browser uses the independent exact oracle for the mathematical candidate, then represents ordinary normal values in the same fixed-width decimal-record form observed through the pinned native API. This separation is deliberate: the display may explain source scheduling without pretending that JavaScript BigInt has reproduced every bounded inequality in to_decimal_double.

Z.3 · Scale one decimal place farther

The fractional product supplies the last digit in parallel

The regular double path selects 10−k−1. After the wide multiplication, high retained bits supply an integral field containing the shorter 15- or 16-digit candidate. A fractional field is multiplied by ten to derive the possible extra digit. Interval-width tests decide whether that digit is present and whether the integral field must move to a neighbor.

The critical scheduling point is visible in the fork: deriving the extra digit does not wait for a division of the integral candidate by ten. The source explicitly states that this removes div10 from the critical path.

Z.4 · Integer to characters

Split groups, not one digit at a time

The scalar path converts an eight-digit integer through bases 10000, 100, and 10. Each stage obtains quotient and remainder together, using multiplication by a precomputed reciprocal and a shift instead of general division. A double is handled as two groups below 108.

SSE and NEON implementations realize the same grouping with lanes, packed BCD-like values, byte addition of '0', and shuffles. The implementation begins this work before it has selected fixed or scientific layout, allowing digit conversion to overlap the layout branch.
