Coonen: scale once, round once

Coonen replaces complete exact expansion with a short computation in an extended binary format: estimate a decimal decade, scale the input into an integer range, and perform the requested rounding once.

3.1 · Output contract

This is not yet a shortest printer

Algorithm B receives the number of significant decimal digits as an input. Its task is to produce exactly that digit field and a decimal exponent, in the current rounding mode.

This distinction matters historically and technically. A shortest printer chooses its own precision by asking when a decimal candidate is sufficient for recovery. Coonen’s binary-to-decimal algorithm is designed for formats such as FORTRAN E output, where the caller has already selected N. If asked for five digits, it returns five digits even when one digit would round-trip.

Coonen also gives the inverse conversion, Algorithm D. It turns a bounded decimal digit string into an exact extended-format integer, scales it by a power of ten, records whether discarded input digits were nonzero, and finally rounds to the destination binary format. This chapter begins with B because it is the direct ancestor of the printing problem.

3.2 · The earlier baseline

Correct rounding by complete expansion

A conceptually direct conversion embeds every binary64 input in a fixed-point buffer wide enough for the entire exponent range, converts the integer and fraction portions exactly, and rounds the resulting decimal buffer. This is dependable, but it performs work proportional to the full expansion rather than the requested output.

The economical alternative starts from the requested number of digits. If five digits are required, the useful target is an integer between 10,000 and 99,999. Once the binary value has been moved into that range, one rounding operation determines all five output digits.

For example, multiplying 0.33333… by 100,000 produces 33,333.33…. Rounding that value to an integer gives the five-digit coefficient 33,333; moving the decimal point back gives 0.33333. As a second example, 123.456 needs only one factor of ten to enter the four-digit range: 1,234.56 rounds to 1,235, which is reported as 1.235 × 102.

The general rule. First identify the decimal decade containing x. Call its exponent LOGX: 123.456 lies in decade 2 because it is between 102 and 103. To obtain N integer digits, move the decimal point by N − LOGX − 1 places. The resulting magnitude should lie in [10N−1, 10N).

3.3 · The main procedure

Algorithm B in five transformations

The original procedure has steps B0 through B8. It first asks “which decimal decade contains the input?” and then asks “how many decimal places move that decade into the requested integer range?” The pseudocode groups adjacent bookkeeping steps while retaining the correction loop and its invariant.

  1. extend x; save an unmodified copy
  2. LOGX ← a lower estimate of floor(log10(abs(x)))
  3. SCALE ← N − LOGX − 1; scale x by 10^SCALE
  4. round the scaled x to an integer in the requested mode
  5. correct the decade if necessary; emit N digits and LOGX

For one third with N = 5, LOGX is −1. The scale is therefore 5 − (−1) − 1 = 5, so the procedure multiplies by 105 and rounds 33,333.33… to 33,333. The coefficient and the remembered decade −1 together mean 3.3333 × 10−1.

If the logarithm estimate is correct, scaling places the magnitude in the desired integer decade. If Algorithm L underestimated by one, the scaled value is approximately ten times too large. The test against 10N detects that case, increments LOGX, restores the saved input, and repeats the scaling. Coonen proves that the branch is taken at most once.

The opposite test, against 10N−1, handles a rarer effect in double conversion: an input only slightly above a power of ten can be nudged below the lower limit by the error in a rounded scale factor. Replacing the result by the lower limit reduces an error already within the established bound.

3.5 · A recurring machine-level idea

Replace division with multiplication by a reciprocal

Several conversion algorithms turn a division into multiplication by a stored approximation. The mathematical identity is elementary:

10 / 7 = 10 · (1 / 7).

A machine usually cannot store 1/7 exactly. Suppose, in a decimal fixed-point analogy, that six digits are retained:

1 / 7 ≈ 0.142857 = 142857 / 106.

The division can then be approximated using an integer multiplication:

10 · 142857 / 106 = 1.428570,

whereas the exact quotient begins 1.428571…. The reciprocal was rounded downward, and multiplication magnified its small error by ten. Nothing mysterious has happened: the division error has been moved into the precomputation of the reciprocal.

Binary implementations choose a scale 2k rather than 106. They store an integer M close to 2k/7 and approximate

n / 7 ≈ (n · M) / 2k.

The final division by 2k is a right shift. The runtime operation is therefore a multiply, a selection of product bits, and sometimes a correction. A proof must still bound the reciprocal error after multiplication and establish that it cannot change the required rounding decision. Modern cached-power algorithms use the same pattern with reciprocals or scaled powers of five.

Important qualification. “Division by a constant becomes a multiply” is an implementation theorem with preconditions, not a syntactic substitution. The required product width, direction of reciprocal rounding, discarded low bits, and possible correction all depend on the accepted input range and output contract.

3.6 · The supporting algorithms

The difficult work is hidden behind “scale”

Algorithm B is short because three subsidiary algorithms establish the properties required by its central scaling operation.

Algorithm L: an underestimate is cheaper than a logarithm

A library logarithm would be excessive here. Algorithm B does not need a finely rounded value of log10(x); it needs only the integer identifying the decimal decade, and it can cheaply detect one particular error. Algorithm L is therefore designed to return either the correct decade or the preceding decade, never a later one.

Begin by normalizing the input as 2e·(1 + f), where 0 ≤ f < 1. The exponent e gives the integer part of the binary logarithm. The fraction f is also a convenient lower estimate of the remaining logarithm because f ≤ log2(1 + f) over this interval.

Consider 12 = 23·1.5. Here e = 3 and f = 0.5, so 3.5 is used in place of log2(12) ≈ 3.585. Multiplication by log10(2) gives approximately 1.05; taking the floor returns decade 1, correctly placing 12 between 10 and 100.

The deliberately low estimate can miss at a decimal power. For 10 = 23·1.25, the preliminary value is 3.25. After conversion to a decimal logarithm it is about 0.978, whose floor is 0 rather than 1. Algorithm B then scales 10 as though it belonged to the preceding decade, obtains an integer that is ten times too large, and corrects the decade once.

The implementation does not perform these calculations with real logarithms. It takes leading exponent and fraction bits as a fixed-point integer, multiplies by a hexadecimal constant slightly below log10(2), and discards the fractional result. The downward choices are the proof: they make an overestimate impossible.

Algorithm S: preserve the fact that low bits existed

Scaling produces more product bits than the extended format retains. Simply chopping them would make a product with a nonzero tail indistinguishable from an exact product. The final rounding step sometimes needs precisely that distinction.

Suppose the unabridged product begins 1.0100 001…, while only the first four fractional bits are retained. Chopping yields 1.0100, but the discarded suffix contains a 1. Algorithm S observes the inexact flag and forces the retained least-significant bit to 1, producing 1.0101. If that bit was already 1, it remains 1.

This operation is not the final rounding of the decimal result. It records one proposition—“some discarded bit was nonzero”—inside the retained value. Later literature normally calls this accumulated information a sticky bit.

Algorithms P and Q: powers are part of the proof

A power of ten factors as 10k = 2k·5k. The power of two changes only the exponent, so exact representability depends on whether the integer 5k fits in the significand. With 64 significand bits, 527 fits and 528 does not. Thus powers through 1027 can be formed exactly; larger powers need rounded constants.

Algorithms P and Q combine a small exact power with one or more table values. The table entries have specified rounding directions, and Q uses no more than three multiplications to cover the double range through 10340. Their error signs and multiplication count determine Algorithm B’s error bound. The table is therefore part of the numerical argument, not merely a cache added for speed.

3.7 · What Coonen proves

Recovery without universal correct rounding

At a fixed decimal precision, one decimal ulp is one step between adjacent possible results. Around the five-digit result 0.33333, that step is 0.00001. An error of 0.019 decimal ulp is therefore 0.019 of that local step, not an absolute error of 0.019.

With exact powers of ten, B has only the final expected rounding. Outside that central range, the rounded scale factor contributes additional error. For full 17-digit double output, Coonen bounds that additional binary-to-decimal error at 0.019 decimal ulp in round-to-nearest mode and 0.054 decimal ulp in a directed mode.

Those figures are not themselves the recovery theorem. Recovery follows by combining the binary-to-decimal bound, the decimal-to-binary bound of Algorithm D, and the relative density of the two formats. For double precision, the resulting total is bounded at approximately 0.97 binary ulp—strictly below the one-ulp separation needed to prevent one binary value from crossing to a neighbor during the round trip.

The margin is narrow. That is why the precision of extended intermediates, the direction of every rounded table entry, and sticky information from discarded bits are correctness conditions rather than optional optimizations.

3.8 · Evidence and implementation status

What is executable now, and what remains

The public implementation currently contains an exact-rational control for Algorithm B, tests for ordinary fixed-precision output and the one-retry decade correction, and an execution trace generated from that implementation. It does not yet claim to reproduce the dissertation’s 64-bit extended rounding behavior. These are foundation tests, not yet the difficult-input corpus required for a correctness claim.
