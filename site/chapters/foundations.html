Two grids and one rounding interval

Before an optimized printer can be understood, the required result must be stated without reference to an implementation. This chapter develops that specification and turns it into an executable, exact oracle.

1.1 · Representation

A double is already an exact number

A binary floating-point value is not an imprecise cloud around a real number. Once its bits have been fixed, it denotes one exact rational number.

For the finite, nonzero values considered first, it is convenient to decode binary64 into an integer significand f and an integer exponent e:

v = (−1)s · f · 2e.

A normal binary64 value has a 53-bit significand: the 52 stored fraction bits together with the implicit leading one. With this integer convention, the unbiased IEEE exponent is reduced by 52. A subnormal has no implicit leading bit and uses the fixed exponent −1074. These choices are not merely notational. They allow all subsequent reasoning to use integers and powers of two.

For example, the bit pattern 3fd3333333333333 decodes as

0.3as binary64 = 5,404,319,552,844,595 · 2−54.

The label “0.3” on the left is the source literal or previously printed text; it is not the exact mathematical value on the right. The right-hand side is exact. The first task of every conversion algorithm is, explicitly or implicitly, to recover this form.

Terminology. Some papers call f a mantissa; others reserve that word for a fractional value in [1,2). This book uses significand for the integer f and states the exponent convention whenever it differs from the one above.

1.2 · Baseline

The naive exact printer

If e is nonnegative, exact printing is only an integer shift: f << e. If e = −n is negative, the identity

f · 2−n = f · 5n / 10n

gives a direct algorithm. Compute the integer f · 5ⁿ, pad it to at least n+1 digits, and insert a decimal point n places from the right. The browser implementation on this site performs exactly these BigInt operations.

Applied to the preceding example, the algorithm obtains

0.299999999999999988897769753748434595763683319091796875

This string describes the stored value completely. It is also a poor default representation. It exposes details of the binary approximation that the author of the literal did not write, consumes far more space than necessary, and obscures equality at the level at which most programs exchange numbers.

The naive algorithm nevertheless has two important roles. First, it separates exactness from usefulness: the difficulty of printing a double is not caused by an inability to compute its exact decimal expansion. Second, it supplies a simple operation against which the more selective algorithms can be checked.

1.3 · Problem statement

Several conversions, not one

The phrase “convert a double to a string” leaves the output contract unspecified. Historically important algorithms address different contracts, and a performance comparison is meaningful only after the contract has been fixed.

ContractRequirementTypical use
Exact expansionThe decimal denotes precisely v.Diagnostics, proofs, exact interchange.
Fixed significant digitsRound v to a requested number of decimal digits and rounding mode.Scientific and engineering formats.
Fixed fraction digitsRound at a requested position after the decimal point.Tables, monetary-style display.
Round-trip or recoveryParsing the result returns the original binary value.Serialization and source literals.
Shortest round tripRound trip, using the fewest significant decimal digits.Default language and JSON formatting.
Closest shortestAmong shortest round-tripping decimals, choose the one nearest v, with a stated tie rule.The Steele–White quality criteria and modern formatters.

Coonen’s economical Algorithm B, studied in the next chapter, accepts a requested digit count. Dragon4 and the later shortest algorithms instead determine the digit count from the rounding interval. Grisu2 guarantees recovery but may produce more digits than necessary; Grisu3 produces a shortest result or rejects its input. Keeping these distinctions visible prevents an apparent speedup from being obtained by solving an easier problem.

1.4 · Geometry of parsing

Replace the value with its preimage

Let v⁻ and v⁺ be the adjacent binary64 values below and above a finite value v. Under round-to-nearest parsing, the transition between v⁻ and v occurs at their arithmetic midpoint; the transition between v and v⁺ occurs at the corresponding upper midpoint:

m⁻ = (v⁻ + v) / 2,    m⁺ = (v + v⁺) / 2.

Every real number strictly between m⁻ and m⁺ parses to v. The treatment of the endpoints follows the ties-to-even rule. If the least significant bit of v’s significand is zero, v is the even neighbor at both boundaries and the interval is closed. If that bit is one, the neighboring values win the ties and the interval is open.

I(v) = [m⁻,m⁺] when f is even;    I(v) = (m⁻,m⁺) when f is odd.

The distances to the two boundaries are usually equal. At an exact power of two, however, the predecessor belongs to a binade with half the spacing. The lower boundary is then closer than the upper boundary. Correct printers therefore carry two margins or construct both endpoints; assuming a symmetric interval fails precisely at a structurally important class of inputs.

The shortest-conversion problem can now be stated without mentioning digits or code:

Find the coarsest decimal grid containing a point in I(v). Among the points of that grid inside the interval, choose the point closest to v, and apply the specified decimal tie rule if necessary.

A decimal with coefficient d and exponent k is the rational d · 10ᵏ. Changing k changes the spacing of the decimal grid. Thus the picture in the explorer is not an analogy added after the algorithm: it is the problem itself.

1.5 · Executable specification

An independent exact oracle

Optimized printers use fixed-width approximations, carefully bounded products, and specialized candidate arguments. Their tests should not decide correctness by repeating the same logic in a slower syntax. This project therefore includes a separate oracle whose only arithmetic objects are exact BigInt rationals.

  1. decode the bits as the exact rational v = f · 2^e
  2. optionally expand v exactly using f · 5^(−e) / 10^(−e)
  3. construct v−, v+, and the exact midpoint interval I(v)
  4. for significant-digit counts n = 1 … 17, choose grid step 10^(q−n+1)
  5. find all integer coefficients d whose grid points d · 10^k lie in I(v)
  6. return the closest admissible coefficient; break an exact tie toward even

For a given grid exponent k, the coefficient bounds are obtained by exact division of the interval endpoints by 10ᵏ, followed by ceiling at the lower endpoint and floor at the upper endpoint. An open endpoint is excluded if this division is exact. No candidate is rounded to binary floating point during the search.

Seventeen significant digits suffice for binary64 round-trip output. The oracle nevertheless derives the first admissible digit count by search, rather than calling the host language’s formatter. The resulting decimal is parsed back only as an additional test, not as the argument for its correctness.

Independence. The oracle shares the binary64 decoder and exact midpoint definition with the visual explorer. It does not share cached-power tables, multiplication/shift approximations, trailing-zero tests, or candidate-selection branches with Ryū, Schubfach, or Dragonbox.

The trace deliberately begins with the long exact expansion. The transition from that expansion to the rounding interval is the conceptual step on which every shortest printer depends: once the interval is known, equality with v is unnecessary. Membership in I(v) is sufficient.

1.7 · Scope

What the oracle does not claim

The BigInt search is a specification and a test instrument. It is not offered as a fast production formatter. It currently treats the finite nonzero path; signed zero, infinities, and NaNs are formatting policies rather than shortest-decimal questions and are tested separately by production wrappers. Text layout—when to use fixed or scientific notation—is also separate from the selection of a decimal coefficient and exponent.

This separation will recur throughout the book. Several modern libraries call their core operation “binary to decimal” because it returns an integer coefficient and a decimal exponent. Turning that pair into characters can cost as much as, or more than, the numerical conversion. Comparisons later in the book will state explicitly which part is measured.
