A practical IEEE 754 binary64 primer

The conversion chapters assume that a double can be decoded into a sign, an integer significand, and a power of two. This primer develops that model from the 64 stored bits and accounts for the places where the grid changes shape.

1.1 · Scope and model

A format for values, and rules for operations

IEEE 754 defines floating-point formats and the behavior of operations on them. This site uses its 64-bit binary format, binary64—the format ordinarily meant by an IEEE double.

Binary64 does not store an arbitrary real number. Its 64 bits select one member of a finite set: finite numbers, two signed zeros, two infinities, and NaNs. For the conversion algorithms, the useful way to decode a finite nonzero value is as a sign, an integer, and a binary shift. The integer supplies the significant bits; the shift says where their binary point belongs.

Exact finite-value modelv = (−1)s × c × 2qs is the sign bit, c an integer significand, and q an integer exponent.

This decoded form is exact. Approximation arises when a source number is not in the binary64 set, or when the exact result of an operation is not representable and must be rounded to one of the available values.

Language qualification. IEEE 754 names the format binary64. C, C++, Java, JavaScript, and many other environments commonly expose it as double or Number, but language and ABI rules determine the precise type mapping.

1.2 · Normal finite values

One guaranteed bit buys one extra bit of precision

Before deciding what to store, put every nonzero binary value into scientific notation. Move the binary point until exactly one digit remains to its left. That digit cannot be 0—otherwise the number would still begin with zeros—so it is always 1.

Normal binary64 values use exactly this normalized form. Because the first significand bit is known in advance, writing it into every value would waste a storage bit. Binary64 stores only the 52 bits after the point and restores the leading 1 while decoding. Read as an integer, every normal significand therefore has exactly 53 binary digits and its first digit is always 1. The omitted leading digit is the extra precision bit.

Two significand conventions describe the same value

There are two equally valid places to imagine the point. Coonen and many numerical descriptions use a fractional significand in [1, 2). Conversion implementations often use the same bits as a 53-bit integer. Nothing in the stored value changes: moving the point 52 binary places in the significand is exactly cancelled by subtracting 52 from the attached exponent.

1.4 · Precision and spacing

Binary64 has 53 significant bits, not fixed decimal places

The implicit leading bit and 52 stored fraction bits give normal values 53 bits of precision. This is roughly 15.95 decimal digits: every decimal number with 15 significant digits can be recovered through binary64, while some binary64 values require 17 decimal digits for guaranteed recovery. These statements concern significant digits, not digits after the decimal point.

For a fixed integer e, the positive normal values in [2e, 2e+1) have one exponent and constant spacing 2e−52. Such a region is called a binade. It contains 252 fraction-field choices.

Local spacing factone local step = one ulp = 2e−52This holds throughout the normal binade [2e, 2e+1).

One ulp is one local step. Near 1 on its upper side, consecutive values differ by 2−52. Moving the fraction field by one therefore moves the value by one ulp. “Half an ulp” means half the local gap; its absolute size changes when the exponent changes.

The fixed number of significand bits gives approximately constant relative precision. Absolute precision is not constant: binary64 distinguishes much smaller differences near 1 than near 10300.

1.5 · The boundary at 1

The spacing doubles at an exact power of two

The value 1 is the first point in the binade [1,2). Its successor is 1 + 2−52. Its predecessor belongs to [½,1) and is 1 − 2−53. The lower neighbor is therefore only half as far from 1 as the upper neighbor.

This asymmetry matters to conversion. The lower and upper parsing boundaries need not be equally distant from the selected value. Algorithms must carry two margins, construct both endpoints, or use an equivalent specialized case.

1.6 · Gradual underflow

Subnormal values continue the grid to zero

If the exponent field is zero, the implicit leading one is absent. The stored 52-bit fraction is used directly as an integer. Each increment moves one minimum binary64 step, so positive subnormal values count upward from zero in multiples of 2−1074.

Subnormal decoding factv = F × 2−1074For a positive nonzero subnormal, 1 ≤ F < 252.

The smallest positive binary64 value is therefore 2−1074, approximately 4.94 × 10−324. The positive subnormals form a uniformly spaced continuation from zero. Their spacing remains 2−1074 through the transition to the smallest normal value, 2−1022.

A subnormal can have fewer significant nonzero bits than a normal value. This gradual loss of relative precision is preferable to an abrupt gap between the smallest normal value and zero. Conversion implementations commonly normalize a subnormal significand internally and then reuse their main path.

1.7 · Operations

Exact arithmetic is rounded back to the format

The exact sum, product, quotient, square root, or parsed decimal often lies between binary64 values. IEEE 754 defines rounding directions that select a representable result. The commonly used direction chooses the nearest value; directed modes choose toward zero, toward positive infinity, or toward negative infinity.

Rounding is conceptually performed after the exact result has been determined. An implementation may use guard, round, and sticky information instead of constructing that exact result in full, but it must reach the prescribed choice. The next chapter introduces the exact midpoint rule used by round-to-nearest parsing at the moment those midpoints become part of the conversion problem.

Values are exact; operations may round. Saying that binary64(0.3) is exact does not say that it equals the real number 3/10. It says that its bit pattern denotes one exact rational. The rounding occurred when 3/10 was mapped to that pattern.

1.8 · Non-ordinary encodings

Signed zeros, infinities, and NaNs are format cases

Binary64 has both +0 and −0. They compare equal numerically in ordinary comparisons, but retain different sign bits; operations such as reciprocal and some branch-sensitive functions can distinguish them. A formatter must therefore have an explicit signed-zero policy.

Exponent field 2047 with a zero fraction denotes +∞ or −∞. A nonzero fraction denotes a NaN. NaNs can carry payload and quiet/signaling information, although language and serialization formats differ in what they preserve. None of these values participates in the shortest finite-decimal search. Production formatters classify them before entering their numerical conversion path.

1.9 · What later chapters assume

Decode first; then reason with integers

Every finite nonzero binary64 value can be reduced to an integer significand and a power of two. Neighboring values usually have equal spacing, but powers of two have an asymmetric predecessor gap. Subnormal values continue at one fixed minimum spacing. Zeros, infinities, and NaNs are classified outside the finite conversion algorithm.

The next chapter overlays a decimal grid, defines the parsing interval and its endpoint rule, and distinguishes exact, fixed-precision, recovery, and shortest output. From that point onward, the discussion concerns how algorithms find a suitable decimal—not how the 64 input bits are interpreted.
