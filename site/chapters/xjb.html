xjb: make the last digit local

Instead of first producing a candidate and then dividing it by ten, xjb scales one decimal place farther. The integer prefix, the possible final digit, and both shortening opportunities are then visible in one small neighborhood.

X.1 · The implementation question

The theorem is inherited; the dependency chain changes

Schubfach already tells us which decimal integers lie in the parsing interval. xjb asks whether the final digit can be exposed without placing an integer division by ten on the critical path.

Let the exact positive input be v = c · 2q. The binary spacing exponent q determines a decimal exponent k. xjb then scales by 10−k−1: one power of ten farther than the exponent of the decimal record it will return.

After this scale, the value has the form m + n, where m is an integer and 0 ≤ n < 1. The decimal coefficient is assembled as 10m + one. Thus m already supplies every digit except the last; the fractional position of n determines one.

X.2 · Exact decimal-space geometry

There are only eleven positions worth inspecting

The shaded band is the input’s exact parsing interval after the same decimal scale. The blue marker is the exact binary rational—not the decimal typed into the input box. Each numbered point is a possible value of one. Hovering, focusing, or tapping a point reveals its full decimal value and whether it is admitted, but the selected point and the two shortening exits remain visible without interaction.

The browser computes this geometry with unbounded integers. It uses xjb’s current exponent approximation, but it does not emulate the cached 128-bit power or the retained product words. That makes the picture a check of the mathematical decision, not a performance port.

X.3 · The two endpoint tests

Last digit 0 and carry 10 erase a digit

For an interior point, such as 2, the returned coefficient really needs the new last digit: 10m + 2. The points 0 and 10 are different. Choosing 0 gives 10m; choosing 10 gives 10(m + 1). In either case the coefficient ends in zero, so normalization can remove that zero and increase the decimal exponent. Admission of either endpoint therefore proves that one fewer significant digit is sufficient.

The ordinary fallback is round-to-nearest in this local ten-cell ruler. That result is used only if neither shorter endpoint lies in the parsing interval. Equality at a binary midpoint follows the parser’s endpoint rule; the parity of the stored binary significand determines whether the boundary belongs to this input.

X.4 · From exact geometry to machine operations

The source stores the same facts in a product window

The pinned binary64 implementation approximates floor(q log10 2) with a fixed multiply and shift, selects a cached 128-bit power of ten, and forms the high part of a wide product. Its upper word supplies the prefix. A lower retained word represents the fractional position n; multiplying that word by ten supplies the provisional last digit.

A quantity named half_ulp represents the relevant scaled interval margin. Two comparisons replace the provisional digit with 0 or 10 when an endpoint is admissible. This is the bounded-arithmetic realization of the three outcomes shown above.

The repository supplies full and compact tables. For binary64 it reports 15,336 bytes for the full lookup data and 368 bytes for the compact variant. These are upstream table sizes, not measurements of complete programs; the compact path reconstructs powers and spends additional arithmetic to save read-only storage.

X.5 · Unequal neighborhoods

A power of two has a closer predecessor boundary

At an exact normal power of two, the predecessor belongs to the previous binade and is only half as far away as the successor. The preset labelled “unequal margins” makes this asymmetry visible. The source recognizes the case from a zero stored fraction and adjusts the margin tests. No separate conceptual algorithm is required: the same eleven positions are tested against a band whose left and right widths differ.

Subnormal values use a separate source path and are intentionally outside this microscope. Their spacing and boundary geometry are introduced in the IEEE-754 refresher rather than repeated here.
