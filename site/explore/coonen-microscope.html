The scaling microscope

Coonen prints a requested number of digits with one multiplication and one rounding. Only the power of ten can be slightly wrong, and we can see exactly how wrong.

Zoom in on the one number Coonen rounds. After scaling, “the N-digit answer” is “the nearest integer”, and the only error is a band of provably bounded width around the exact value. The printed digit can be wrong only when that band straddles the .5 line.

Coonen 1984 · The idea

Printing N digits is rounding one number

To print x with N significant digits, multiply it by the power of ten that puts exactly N digits in front of the decimal point, then round to the nearest integer.

For example, π to five digits: π × 104 = 31415.926…, the nearest integer is 31416, so the answer is 3.1416. The exponent that makes this work is

digits = round(x × 10SCALE), SCALE = N − 1 − ⌊log₁₀ x⌋

With exact arithmetic that is the whole algorithm. Jerome Coonen’s contribution (in his 1984 dissertation, chapter 7, the basis of the conversion rules in IEEE 754-1985) is to show that you don’t need exact arithmetic. The multiplication can be done once, in a register with a 64-bit significand, and the rounding happens once, at the end. Only one ingredient can be slightly wrong: the power of ten. Its error is known in advance and is tiny.

What to remember

A double is an integer times a power of two: x = m · 2e with m < 253. So x · 10SCALE is an exact rational; this page computes it exactly (with BigInt) to check Coonen.

The extended format (the x87 “long double”) has a 64-bit significand. A number fits exactly if it is a 64-bit integer times a power of two.

10k = 5k · 2k, so 10k fits in 64 bits exactly when 5k does. That holds up to k = 27, because 527 ≈ 7.5·1018 < 264 ≈ 1.8·1019 < 528.

ulp₁₀ means one unit in the last printed digit. After scaling, that unit is simply 1: neighbouring N-digit outputs are neighbouring integers.

Fixed N, not shortest. Coonen answers “give me N digits”, like printf("%.16e"). It does not search for the shortest string that reads back, as Grisu, Ryū and friends do. With N = 17 every double reads back correctly (see the budget at the end); a shortest printer would need an outer loop over N with a read-back test.

Algorithm B · step by step

One conversion, card by card

Pick a double. The cards follow Coonen’s Algorithm B: guess the decade cheaply, choose SCALE, build 10SCALE from a small table, multiply once, round once, and check that the integer has N digits. Everything is simulated bit for bit, with a 64-bit significand.

The fuzz band

The only liar is the power of ten

Look at what can go wrong in those cards. Putting x into the 64-bit register is exact. The multiplication loses nothing, thanks to a trick explained below. The rounding to an integer is exactly the rounding we asked for. What’s left is z, the power of ten: when |SCALE| > 27 it can’t be stored exactly, so z = 10SCALE · (1 + δ).

Coonen therefore rounds x · z = Y · (1 + δ) instead of the exact Y = x · 10SCALE. The number being rounded is shifted by Y · δ (for a division, by about −Y · δ). Since Y is below 10N, and Coonen proves |δ| ≤ 3.5 · 2−64 for rounding to nearest:

|shift| < 10N · |δ| ≤ 1017 · 3.5 · 2−64 ≈ 0.019 ulp₁₀

So “does Coonen print the right last digit?” becomes a picture: a band at most ±0.019 wide around the exact scaled value. The correct answer rounds Y, Coonen rounds a point inside the band. They can disagree only if the band straddles the decision line at .5. Fewer digits make the band 10× thinner per digit, while the integers stay where they are.

Algorithm Q · a table of four numbers

Where the band is zero

Coonen builds 10|SCALE| from exact powers up to 1027 and a table of just four extended numbers: 1027 (exact), 1055, 10108 and 10206 (each rounded to nearest). Any power up to 10340 takes at most three multiplications and at most two rounded table entries; 10340 = 10206 · 10108 · 1026. That covers the whole double range: 5e−324 needs SCALE = 340, and the largest double needs SCALE = −292, a division.

When |SCALE| ≤ 27 the band has width zero, and Coonen is correctly rounded, full stop. For N = 17 that is every x from 10−11 up to 1044. This zone is the origin of the “correctly rounded” ranges in Table 3 of IEEE 754-1985. Outside it, the bars show the largest shift that the actual table values can cause in each decade.

Algorithm S · the multiply that loses nothing

Chop, but remember

The product x · z is computed in the 64-bit register, too. Why isn’t that a second rounding error? Coonen’s Algorithm S multiplies with rounding toward zero (it chops), then ORs the “inexact” flag into the last bit of the result. That last bit becomes a sticky bit: it says “something non-zero was cut off”.

In the final pass the integer part needs at most 57 bits (1017 < 257), so at least 7 fraction bits remain. The half-way point .5 and the integers lie on that grid at even positions. When bits were cut off, the chopped value gets its last bit forced to 1. That makes it odd, so it can never land exactly on a decision point, and it stays on the same side as the true product. (When nothing was cut off, the register already holds the exact product.) Rounding the register therefore gives exactly the same integer as rounding the exact product. (Today this trick is called round to odd; Coonen describes it as letting the chopped bits “participate correctly as guard bits”.)

Experiment

Catch a misround

How often does the band actually flip a digit? Draw random doubles, run Coonen on each, and compare against the exact answer. Each sample that lands near a decision line becomes a dot: across is its distance from the line, up is the shift caused by the power of ten. A digit flips only when the shift carries the value across the line, which means a dot inside the red wedges.

Error analysis · §3.4 recovery

Accurate enough, by design

The misrounds are not a bug; they are the price of a deliberate trade. Coonen’s own correctly rounded routine for doubles needed a 1400-bit decimal buffer and a 1000-bit binary buffer. Algorithm B needs four table constants, one multiply or divide, and a register only 11 bits wider than a double. In return he proves:

  • Correct rounding whenever |SCALE| ≤ 27, which covers every everyday magnitude.
  • Elsewhere, at most 0.5 + 0.019 ulp₁₀ from x when rounding to nearest, so the printed value is always one of the two neighbours of x: never off by a whole digit.
  • Directed modes always err in the requested direction.
  • 17-digit output always reads back to the same double.

The last point is a budget. At 17 digits an ulp₁₀ is at most 10−16/2−53 ≈ 0.9007 of an ulp₂ (a unit in the double’s last place). Printing costs 0.9007 · (0.5 + 0.019) ulp₂. Reading back with Coonen’s own Algorithm D costs at most 0.5 + 0.0017 ulp₂. If the sum stays below 1 ulp₂, the string can only read back to x.

Directed rounding modes (toward 0, up, down)

In a directed mode the answer must not lie on the wrong side of x. Coonen ensures that by rounding the power of ten in a known direction too (step S0). If the result should grow in magnitude (rounding up and x > 0, or rounding down and x < 0), z is rounded up; otherwise down. When SCALE < 0 the product is a division, so the direction flips. Table entries are stored rounded to nearest, together with a ±1 “pfix” that moves them one unit in the last place when a mode needs the other side.

So in a directed mode the band is one-sided: the computed value always sits on the requested side of the exact one. The decision points are the integers themselves, and the bound grows to 5 · 2−63, i.e. 0.054 ulp₁₀ at 17 digits. With the three results Xdown, Xnearest, Xup and the correctly rounded Cdown, Cup, Coonen shows the interlacing Xdown ≤ Cdown ≤ Xnearest ≤ Cup ≤ Xup. That makes a handy test against any correctly rounded implementation. Switch the rounding control above to see the one-sided bands.

Summary

The whole algorithm

Algorithms B, S, L and Q from the dissertation, condensed. ext is the 64-bit-significand format; every operation on it is a single IEEE operation.

function coonen(x, N, mode):                 // B: N significant digits
  logx = floor(LOG2 × (e + 0.f))             // L: x = 2^e × 1.f; never too high,
                                             //    about 2% of the time one too low
  loop:
    scale = N − 1 − logx                     // B3
    z = pow10(|scale|, direction(mode))      // Q: table bricks; exact if |scale| ≤ 27
    t = (scale ≥ 0 ? x × z : x / z)          // S2: in ext, rounded toward zero
    if inexact: t = t OR 1                   // S3: sticky bit in the last place
    r = roundToInteger(t, mode)              // B5: the one rounding that matters
    if r ≥ 10^N: logx += 1; continue         // B6: logx was low, or a carry: retry once
    if r < 10^(N−1): r = 10^(N−1)            //     (rare safety net, never seen here)
    return digits(r), exponent logx          // B7, B8: d1.d2…dN × 10^logx

function pow10(n, dir):                      // Q
  z = 1
  for (p, entry) in [(206, T206), (108, T108), (55, T55), (27, 10^27)]:
    if n ≥ p: z = z × fix(entry, dir); n −= p  // rounded in direction dir
  return z × 10^n                            // 10^n exact: n ≤ 27

About the source: the dissertation’s table stores 1027 exactly and 1055 = 0.D0CF4B50CFE2076616 · 2183 ≈ 1055·(1+2−76), 10108 = 0.DA01EE641A708DEA16 · 2359 ≈ 10108·(1+2−67) and 10206 = 0.9F79A169BD203E4116 · 2685 ≈ 10206·(1−2−67). 27 + 55 + 108 + 206 reaches 10340 with at most two rounded entries. This page recomputes the entries from exact powers of ten; they match the printed hex digits.
