Pocket Coonen

Shrink the number formats until every value fits on a sticky note. Check Coonen's single multiply by hand, then switch off his safeguards one at a time and watch real doubles come out wrong.

A toy version (6-bit input, 3 digits, 12-bit register) makes the three tricks easy to check with a phone calculator. A mapping table then carries them up to binary64, and a fuzzer finds real counterexamples when one safeguard is removed.

1 · The recipe

Scale once, round once

Coonen's Algorithm B (1984) answers a different question than the shortest-digit printers. The caller chooses the number of digits N, as with printf("%.16e"), and gets exactly N digits back. It does not search for the shortest string.

  1. Estimate the decade. LOGX = ⌊log10 x⌋. The cheap estimate can be one too low, but never too high. B2
  2. Pick the scale. SCALE = N − LOGX − 1, so x · 10SCALE has N digits before the point. B3
  3. Multiply by z ≈ 10SCALE in a register wider than the input (or divide by 10−SCALE when SCALE is negative). B4 · Algorithm S
  4. Round to an integer in the current rounding mode. That integer is the N digits. B5
  5. Check the length. If the integer has N + 1 digits, LOGX was too low: add 1 and go back to step 2, at most once. B6

Everything interesting happens in step 3. For doubles the register has 64 bits: wider than the 53-bit input, but not infinitely wide. Both the power of ten and the product can therefore be slightly off. Coonen adds three safeguards:

  • Chop, then set a sticky bit. This keeps the multiply from adding any error of its own.
  • Round z in the right direction. This makes “round up” and “round down” keep their promise.
  • The B6 length check. This guarantees exactly N digits.

One error source remains: the power of ten itself. It is exact up to 1027 and only a tiny bit off beyond that.

Remember

A double is an integer significand of at most 53 bits times a power of two. A p-bit register holds an integer exactly only if the integer has at most p bits.

10k = 2k · 5k, and the 2k is only an exponent. So 10k is exact in p bits exactly when 5k < 2p.

IEEE 754 has four rounding modes: to nearest (a tie goes to the even neighbour), toward 0, toward +∞ and toward −∞. The last three are the directed modes.

2 · Pocket formats

Shrink everything to fit a sticky note

With doubles, the numbers in step 3 have 17 to 20 digits. We make every format smaller while keeping the same relationships. Then every intermediate value is a three- or four-digit number:

  • Input: a 6-bit significand (32 to 63) times 2e. A double has 53 bits.
  • Output: N = 3 digits, the smallest N with 101−N < 2−6. The same rule gives 17 for doubles.
  • Register: 12 bits. A 3-digit integer is below 1000 < 210, so at least 2 bits are left after the binary point.
  • Exact powers of ten: 100 to 105, because 55 = 3125 < 212 = 4096 < 56 = 15625.

3 · Card A

A wobbly power of ten misrounds

Once z is rounded, the product is off by a factor (1 + δ). This usually does not matter. It matters only when the exact product lies close to a rounding boundary.

4 · Card B

The halfway trap and the sticky bit

Here z is exact. Rounding twice (the product to the register, then the register to an integer) can still go wrong. Coonen's fix: chop the product, and if anything was chopped off, set the last bit.

Today this trick is called round to odd: chop, and force the last bit to 1 if anything was lost. It makes a second rounding safe as long as that rounding is at least two bits coarser. Coonen's register always has those two bits spare. Coonen does not use the name.

5 · Card C

Pointing the right way

In a directed mode the promise is one-sided. “Toward +∞” must never print a value below x. A z rounded to nearest may be a little too small, and then the result can land on the wrong side. Coonen rounds z itself in the direction the result must move (step S0). This card also needs the sticky bit.

The S0 rule in full: work out whether the result must grow in magnitude (toward +∞ with x > 0, or toward −∞ with x < 0). If so, round z up; otherwise round z down. When SCALE < 0 we divide by z, so flip that choice. To nearest, z is simply rounded to nearest.

Don't carry the toy's error rate over to doubles. The toy's extra error can reach 0.24 of a digit. Coonen's bound for doubles is 0.019, more than ten times smaller: the 64-bit register has 11 bits more than the input, while the toy has only 6 bits more. The toy is built to fail often, so that the failures are easy to find.

8 · Real doubles

The same moves at full size

This is the same simulator with a 64-bit register, Coonen's real Algorithm L for the decade and Algorithm Q for the powers of ten. Things to try:

  • 0.1: the log estimate is one too low, so B6 retries.
  • 1.0439 and 0.5308290954995201: the sticky bit decides the last digit.
  • 1.0408207851369739e-12: z = 1028 is rounded, and the result is not correctly rounded.

9 · Switch off a safeguard

Break it on purpose

Every odd-looking detail exists because of a concrete failure. Pick a safeguard to remove, and the fuzzer converts random doubles with N = 17. It checks each result against Coonen's promises:

  • correctly rounded whenever z is exact;
  • never on the wrong side in a directed mode;
  • exactly N digits;
  • at most 0.519 ulp of error to nearest, 1.054 ulp when directed;
  • 17 digits read back to the same double.

Results that are not correctly rounded, where z was rounded, are counted separately. Those are allowed.

A safeguard you cannot switch off here is the lower bound in Algorithm L. The estimate e.f ≤ log2 x, and log10 2 is chopped, bumped up by one unit when e.f < 0. As a result LOGX is never too high. Coonen explains why this matters: if LOGX could also be too high, B6 would have to retry in both directions, and a value very close to a power of ten could then bounce between two scales forever.

10 · What you get

Accurate enough, by design

  • Fixed N, not shortest. Algorithm B prints exactly the N digits you asked for. A shortest printer would need an outer loop over N with a read-back test.
  • Correctly rounded whenever −27 ≤ SCALE ≤ 27. For 17 digits that means results from 10−11 to 1044. This range is the source of Table 3 in IEEE 754-1985.
  • Bounded error elsewhere. To nearest, the extra error is at most 0.019 of the last digit. In the directed modes the result is always on the correct side, with at most 0.054 extra. This is a deliberate trade: no bignums, a four-entry table and one multiply.
  • 17 digits always read back. Coonen's budget (§3.4) is 0.9 × (0.5 + 0.019) + 0.5017 ≈ 0.97 of a binary ulp, which is less than 1. The fuzzer's round-trip counter stays at zero.
